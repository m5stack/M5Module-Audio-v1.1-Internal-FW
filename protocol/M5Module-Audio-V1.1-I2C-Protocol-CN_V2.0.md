# M5Stack Module-Audio I²C 控制协议（固件标识 `0x02`）

## 1. 基本信息

| 项目 | 说明 |
| :--- | :--- |
| 总线 | I²C，从机模式 |
| 设备 | M5Stack Module-Audio |
| 默认 I²C 地址（7 位） | `0x33` |
| 可配置 I²C 地址范围（7 位） | `0x08 ~ 0x77`，不含 ES8388 使用的 `0x10` |
| 通信速率 | `400 kbit/s`（I²C Fast-mode） |
| 寄存器地址宽度 | `8 bit` |
| 寄存器数据宽度 | `8 bit` |
| 地址自增 | `0x10 ~ 0x11`、`0x40 ~ 0x48` 支持连续读写；`0xE0 ~ 0xEB` 支持连续读取 |
| Clock Stretching | 支持 |
| General Call | 不支持 |
| 固件版本 | 当前寄存器 `0xFE` 返回 `0x02`；后续迭代可能变更 |

### 1.1 访问权限

| 权限 | 含义 |
| :--- | :--- |
| `R` | 只读 |
| `W` | 只写 |
| `R/W` | 可读可写 |
| `Reserved` | 保留，不应访问 |

### 1.2 读写时序

#### 写寄存器

主机在一次写事务中依次发送寄存器地址和数据：

```text
START → SlaveAddr + W → RegisterAddr → Data[0] ... Data[N] → STOP
```

- 除下述连续地址块外，普通寄存器只接受 `1 byte` 数据。
- `0x10 ~ 0x11` 支持连续写入：从 `0x10` 开始最多写入 `2 byte`，从 `0x11` 开始只能写入 `1 byte`。
- `0x40 ~ 0x48` 支持从指定地址开始连续写入，写入长度不得超过该地址到 `0x48` 的剩余空间。
- 写入不支持的值时，设备忽略该次设置，不返回独立错误码。

#### 读寄存器

推荐使用组合事务：先写入目标寄存器地址，再通过重复起始条件读取数据。

```text
START → SlaveAddr + W → RegisterAddr
RESTART → SlaveAddr + R → Data[0] ... Data[N] → STOP
```

- 除下述连续地址块外，普通寄存器读取长度为 `1 byte`。
- 从 `0x10` 读取时可按地址顺序连续读取 `0x10`、`0x11`；从 `0x11` 开始只返回 `0x11`。
- 从 `0x40 ~ 0x48` 读取时可连续读取到 `0x48`，读取长度不得超过剩余数据长度。
- 从 `0xE0 ~ 0xEB` 读取时可连续读取到 `0xEB`，读取长度不得超过剩余 UID 数据长度。
- 协议没有统一状态码。需要确认写入结果时，应回读对应的 `R/W` 寄存器。

## 3. 地址约定

### 3.1 固定系统地址

| 地址 | 名称 | 说明 |
| :--- | :--- | :--- |
| `0xF0` | Save Configuration to Flash | 写入 `0x01` 保存当前可持久化配置 |
| `0xFD` | IAP Upgrade | 写入非零值触发系统复位；IAP 进入条件见 `4.8` |
| `0xFE` | Firmware Version | 读取固件版本号 |
| `0xFF` | I²C Address | 读取或修改设备 7 位 I²C 地址 |

### 3.2 保留地址

| 地址/地址范围 | 类型 | 访问规则 |
| :--- | :--- | :--- |
| `0x01 ~ 0x0F` | `Reserved` | 禁止访问 |
| `0x12 ~ 0x1F` | `Reserved` | 禁止访问 |
| `0x21 ~ 0x2F` | `Reserved` | 禁止访问 |
| `0x31 ~ 0x3F` | `Reserved` | 禁止访问 |
| `0x49 ~ 0xDF` | `Reserved` | 禁止访问 |
| `0xEC ~ 0xEF` | `Reserved` | 禁止访问 |
| `0xF1 ~ 0xFC` | `Reserved` | 禁止访问 |

未定义寄存器不会返回有效协议数据。后续固件可以使用保留地址；主机程序不得依赖当前未定义地址的行为。

## 4. 寄存器详情

### 4.1 Microphone Config

| 地址 | 长度 | 权限 | 功能说明 |
| :--- | :--: | :--: | :--- |
| `0x00` | `1 byte` | `R/W` | 控制 LINE/MIC 通道 |

| 值 | 名称 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `0x00` | `OFF` | 否 | 关闭 LINE/MIC 通道 |
| `0x01` | `ON` | 是 | 打开 LINE/MIC 通道 |

写入立即生效。新值只有在随后向 `0xF0` 写入 `0x01` 后才保存到 Flash。该寄存器不会自动修改 `0x11`；为避免两路麦克风信号同时接入 LINE IN，主机在开启 LINE/MIC 前应先向 `0x11` 写入 `0x00`。

### 4.2 Headphone Mode

| 地址 | 长度 | 权限 | 功能说明 |
| :--- | :--: | :--: | :--- |
| `0x10` | `1 byte` | `R/W` | 选择耳机接口模式 |

| 值 | 名称 | 默认值 | PA2 `HP_MODE_SET` | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `0x00` | `AMERICA_STANDARD` | 是 | 低电平 | 美标（CTIA）模式 |
| `0x01` | `NATIONAL_STANDARD` | 否 | 高电平 | 国标（OMTP）模式 |

写入立即生效。新值只有在随后向 `0xF0` 写入 `0x01` 后才保存到 Flash。

### 4.3 Headphone Microphone Enable

| 地址 | 长度 | 权限 | 功能说明 |
| :--- | :--: | :--: | :--- |
| `0x11` | `1 byte` | `R/W` | 控制耳机麦克风通道 |

| 值 | 名称 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `0x00` | `OFF` | 是 | 关闭耳机麦克风通道 |
| `0x01` | `ON` | 否 | PA0 拉高，打开内部固态继电器，将耳机麦克风信号接入 LINE IN |

注意事项：

1. 该寄存器不保存到 Flash，上电后恢复为 `0x00`。
2. 写入 `0x01` 时固件不检查耳机是否插入；主机应通过 `0x20` 确认耳机状态后再开启。
3. 该寄存器不会自动关闭 `0x00` LINE/MIC 通道。开启耳机麦克风前，主机应先向 `0x00` 写入 `0x00`。
4. 耳机麦克风开启时，LINE/MIC 接口不得连接外置麦克风。
5. `0x10` 和 `0x11` 为连续地址，可从 `0x10` 开始一次连续读写两个寄存器。

主机切换到耳机麦克风的推荐顺序：

```text
1. 读取 0x20，确认返回 0x01
2. 向 0x00 写入 0x00，关闭 LINE/MIC 通道
3. 向 0x11 写入 0x01，开启耳机麦克风通道
```

主机切换回 LINE/MIC 的推荐顺序：

```text
1. 向 0x11 写入 0x00，关闭耳机麦克风通道
2. 向 0x00 写入 0x01，开启 LINE/MIC 通道
```

### 4.4 Headphone Insert Status

| 地址 | 长度 | 权限 | 功能说明 |
| :--- | :--: | :--: | :--- |
| `0x20` | `1 byte` | `R` | 读取耳机插入检测状态 |

| 值 | 名称 | 说明 |
| :--- | :--- | :--- |
| `0x00` | `HEADPHONE_UNPLUG` | 未插入耳机 |
| `0x01` | `HEADPHONE_INSERTION` | 已插入耳机 |

检测引脚高电平表示耳机插入，低电平表示耳机拔出。固件每 `5 ms` 采样一次，连续 `3` 次稳定后更新状态，因此从实际插拔到 `0x20` 更新通常存在约 `10 ~ 15 ms` 延迟。

### 4.5 RGB Brightness

| 地址 | 长度 | 权限 | 功能说明 |
| :--- | :--: | :--: | :--- |
| `0x30` | `1 byte` | `R/W` | 设置 3 颗 RGB LED 的全局亮度 |

| 取值范围 | 默认值 | 单位 | 说明 |
| :--- | :--- | :--- | :--- |
| `0 ~ 100` | `10`（`0x0A`） | 百分比等级 | `0` 为关闭输出，`100` 为最高亮度 |

写入后设置 RGB 更新标志，由主循环更新 LED 输出。新值只有在随后向 `0xF0` 写入 `0x01` 后才保存到 Flash；超出范围的值会被忽略。

### 4.6 RGB LED

| 地址范围 | 长度 | 权限 | 功能说明 |
| :--- | :--: | :--: | :--- |
| `0x40 ~ 0x48` | `9 byte` | `R/W` | 设置或读取 3 颗 RGB LED 的颜色分量 |

| 地址 | 字段 | 取值范围 | 默认值 |
| :--- | :--- | :--- | :--- |
| `0x40` | `LED1_R` | `0 ~ 255` | `0x00` |
| `0x41` | `LED1_G` | `0 ~ 255` | `0x00` |
| `0x42` | `LED1_B` | `0 ~ 255` | `0x00` |
| `0x43` | `LED2_R` | `0 ~ 255` | `0x00` |
| `0x44` | `LED2_G` | `0 ~ 255` | `0x00` |
| `0x45` | `LED2_B` | `0 ~ 255` | `0x00` |
| `0x46` | `LED3_R` | `0 ~ 255` | `0x00` |
| `0x47` | `LED3_G` | `0 ~ 255` | `0x00` |
| `0x48` | `LED3_B` | `0 ~ 255` | `0x00` |

连续写入 3 颗 LED 的示例：

```text
RegisterAddr: 40
Data:         FF 00 00 00 FF 00 00 00 FF
Result:       LED1=红色，LED2=绿色，LED3=蓝色
```

从中间地址连续写入的示例：

```text
RegisterAddr: 44
Data:         80 40 FF
Result:       LED2_G=0x80，LED2_B=0x40，LED3_R=0xFF
```

注意事项：

1. 可从 `0x40 ~ 0x48` 中任意地址开始连续读写，但不能越过 `0x48`。
2. 写入后设置 RGB 更新标志，由主循环更新 LED 输出。
3. RGB 颜色值不保存到 Flash，上电后全部恢复为 `0x00`。
4. 实际输出亮度同时受 `0x30` 全局亮度寄存器影响。

### 4.7 Save Configuration to Flash

| 地址 | 长度 | 权限 | 触发值 | 功能说明 |
| :--- | :--: | :--: | :--- | :--- |
| `0xF0` | `1 byte` | `W` | `0x01` | 保存当前配置到内部 Flash |

保存内容：

- `0x00` Microphone Config
- `0x10` Headphone Mode
- `0x30` RGB Brightness

注意事项：

1. Flash 写入前需要擦除，操作耗时约 `20 ms`；操作期间设备可能暂时无法响应。
2. 为延长 Flash 寿命，应避免频繁写入。
3. 当当前值与 Flash 中已保存的值一致时，固件跳过擦写。
4. `0x11` 和 `0x40 ~ 0x48` 不在保存范围内。

### 4.8 IAP Upgrade

| 地址 | 长度 | 权限 | 触发值 | 功能说明 |
| :--- | :--: | :--: | :--- | :--- |
| `0xFD` | `1 byte` | `W` | `0x01 ~ 0xFF` | 触发 MCU 系统复位 |

写入 `0x00` 不触发操作。触发后当前 I²C 会话立即终止。

进入 IAP 的时序要求：

1. 向应用程序地址的 `0xFD` 写入非零值，触发复位。
2. 复位期间将 SCL 和 SDA 同时保持为低电平。
3. Bootloader 启动约 `30 ms` 后检测两条线；两者均为低电平时进入约 `500 ms` 的初始 IAP 等待窗口，否则跳转回应用程序。
4. 进入 IAP 后使用固定 7 位 I²C 地址 `0x54`。IAP 的固件传输命令不属于本控制寄存器协议，应按单独的 IAP 协议执行。

### 4.9 Firmware Version

| 地址 | 长度 | 权限 | 当前值 | 功能说明 |
| :--- | :--: | :--: | :--- | :--- |
| `0xFE` | `1 byte` | `R` | `0x02` | 读取当前固件版本标识 |

`0xFE` 用于区分固件迭代。主机可以根据该值启用对应版本的新功能，但不应仅因该值不等于旧版本 `0x01` 就拒绝使用与旧版本兼容的基础寄存器。

### 4.10 I²C Address

| 地址 | 长度 | 权限 | 取值范围 | 默认值 | 功能说明 |
| :--- | :--: | :--: | :--- | :--- | :--- |
| `0xFF` | `1 byte` | `R/W` | `0x08 ~ 0x77`，不含 `0x10` | `0x33` | 读取或修改设备 7 位 I²C 地址 |

注意事项：

1. 写入合法新地址后，固件自动保存到内部 Flash，无需再写 `0xF0`。
2. 新地址立即生效；完成写事务后，主机后续访问必须使用新地址。
3. 超出 `0x08 ~ 0x77` 的值以及 `0x10` 会被忽略；`0x10` 已由同一总线上的 ES8388 使用。
4. Flash 写入和 I²C 外设重初始化期间，设备可能暂时无法响应。
5. 启动时若 Flash 中保存的是非法地址或 `0x10`，固件会自动恢复默认地址 `0x33`。

### 4.11 Device UID

| 地址范围 | 长度 | 权限 | 功能说明 |
| :--- | :---: | :---: | :--- |
| `0xE0 ~ 0xEB` | `12 byte` | `R` | 读取 STM32 MCU 的 96 位设备唯一标识符 |

UID 由 `HAL_GetUIDw0()`、`HAL_GetUIDw1()`、`HAL_GetUIDw2()` 读取。三个 32 位字依次映射到 `0xE0 ~ 0xE3`、`0xE4 ~ 0xE7`、`0xE8 ~ 0xEB`，每个字按小端字节顺序返回。

可从 `0xE0 ~ 0xEB` 中任意地址开始连续读取，但不能越过 `0xEB`。该寄存器块只读，写入不会改变 UID。

## 5. 无效访问与错误处理

| 情况 | 设备行为 | 主机建议 |
| :--- | :--- | :--- |
| 写入未定义寄存器 | 不执行有效操作 | 不应访问保留地址 |
| 读取未定义寄存器 | 不保证返回有效数据 | 仅访问总览表列出的 `R` 或 `R/W` 地址 |
| 写入只读寄存器 | 忽略 | 不应向 `0x20`、`0xE0 ~ 0xEB`、`0xFE` 写入 |
| 读取只写寄存器 | 不保证返回有效数据 | 不应读取 `0xF0`、`0xFD` |
| 写入超出范围的值 | 忽略该次设置 | 回读对应寄存器确认结果 |
| RGB 连续写入越过 `0x48` | 整次 RGB 写入被忽略 | 限制长度不超过剩余 RGB 数据 |
| RGB 连续读取越过 `0x48` | 超出部分的返回值不保证 | 读取长度不超过剩余 RGB 数据 |

协议不提供 ACK 状态字节或统一错误码。I²C 总线级 ACK 仅表示从机完成了字节接收，不表示寄存器值一定被接受。
